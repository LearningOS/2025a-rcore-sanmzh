#### 2.1 刚进入 __restore 时，sp 代表了什么值。请指出 __restore 的两种使用情景。

进入 __restore 时，sp 代表的值是：  
**当前内核栈顶，指向 TrapContext 结构体的起始地址。**  
也就是说，sp 指向保存了用户态寄存器、sstatus、sepc、sscratch 等信息的 TrapContext（在内核栈上分配的）。
__restore 的两种使用情景如下：
1. **从内核态返回用户态（trap 返回）**  
当内核处理完 trap（中断/异常/系统调用）后，需要恢复用户态上下文，跳回用户程序继续执行。此时 sp 指向 TrapContext，__restore 负责恢复所有寄存器和状态，然后通过 sret 指令返回用户态。
2. **任务切换（上下文切换）**  
在多任务调度时，内核需要保存/恢复不同任务的 TrapContext。切换到某个任务时，sp 被设置为该任务的 TrapContext 地址，然后调用 __restore 恢复该任务的所有寄存器和状态，跳转回用户态继续运行。
总结：  
- __restore 入口时，sp 始终指向当前要恢复的 TrapContext（在内核栈上）。
- 两种典型场景：trap 返回用户态、任务切换恢复上下文。

#### 2.2 

这几行汇编代码特殊处理了 sstatus、sepc、sscratch 三个 CSR（控制和状态寄存器）：
```riscv
ld t0, 32*8(sp)
ld t1, 33*8(sp)
ld t2, 2*8(sp)
csrw sstatus, t0
csrw sepc, t1
csrw sscratch, t2
```
它们的意义如下：
1. **sstatus（Supervisor Status Register）**  
   - 作用：保存并恢复用户态/内核态的特权级、全局中断使能等关键信息。
   - 意义：恢复后，CPU 能以正确的特权级和中断状态进入用户态，保证用户程序能正常运行。
2. **sepc（Supervisor Exception Program Counter）**  
   - 作用：保存异常/中断发生时的用户态 PC（指令地址）。
   - 意义：恢复后，CPU 会从 sepc 指定的指令继续执行用户程序，实现从 trap 返回。
3. **sscratch（Supervisor Scratch Register）**  
   - 作用：在 trap 过程中临时保存用户栈指针（sp），用于内核和用户栈的切换。
   - 意义：恢复后，sscratch 再次保存用户态 sp，方便下次 trap 时能正确切换回内核栈。
总结：  
这三者分别保证了用户态的特权级/中断状态（sstatus）、继续执行点（sepc）、以及用户栈指针（sscratch）都能被正确恢复，是从内核态安全返回用户态的关键。

#### 2.3

跳过 x2（sp，栈指针）和 x4（tp，线程指针）的原因如下：
1. **x2（sp，栈指针）**  
在 trap 进入和返回时，内核和用户态的 sp 会通过 sscratch 和 csrrw 指令进行专门的切换和保存，不需要像普通寄存器一样直接压栈/出栈。这样可以保证 trap 处理期间内核和用户各自有独立的栈空间，避免混淆。
2. **x4（tp，线程指针）**  
在本实验中，用户程序通常不会用到 tp（线程指针），或者 tp 没有特殊语义，故可以跳过不保存/恢复。这样可以简化上下文切换和 trap 处理逻辑。
总结：  
- sp（x2）由专门机制保存和恢复，不需要像普通寄存器一样处理。
- tp（x4）在当前场景下没有用到，故直接跳过。

#### 2.4

执行 `csrrw sp, sscratch, sp` 之后：
- **sp**：变为用户态的栈指针（即原来保存在 sscratch 里的值），用于恢复用户程序的运行环境。
- **sscratch**：变为内核态的栈指针（即原来在 sp 里的值），为下次 trap 进入时保存内核栈指针做准备。
意义总结：
- sp 恢复为用户态栈，CPU可继续执行用户代码。
- sscratch 保存内核栈，方便下次 trap 时切回内核态。

#### 2.5

在 __restore 过程中，发生状态切换的是最后一条指令：
```riscv
sret
```
原因解释：  
`sret`（Supervisor Return）指令会根据 sstatus 寄存器中的 SPP（Previous Privilege）字段，将 CPU 的特权级切换回 trap 发生前的状态（通常是用户态）。同时，sepc 寄存器的值会被加载到 PC，CPU 跳转回用户程序继续执行。因此，执行 `sret` 后，CPU 从内核态切换回用户态，恢复用户程序的运行环境。

#### 2.6

执行 `csrrw sp, sscratch, sp` 之后：
- **sp**：变为内核栈指针（原来保存在 sscratch 里的值），用于在内核态处理 trap（异常/中断/系统调用）。
- **sscratch**：变为用户栈指针（原来在 sp 里的值），用于后续 trap 返回时恢复用户态栈。
意义总结：
- sp 切换到内核栈，方便内核安全处理异常。
- sscratch 保存用户栈，trap 返回时能正确切回用户态。

#### 2.7

从用户态（U态）进入内核态（S态）是由 trap（异常/中断/系统调用）触发的，具体发生在执行如下指令时：
```riscv
ecall
```
或其他异常/中断相关指令（如非法指令、定时器中断等）。  
这些指令会使 CPU 自动切换到 S 态，并跳转到内核 trap 入口（__alltraps）。
